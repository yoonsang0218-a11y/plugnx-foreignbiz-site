## 0. 결론 (Answer First)

**엣지는 개별 기능이 아니라 "재직 라이프사이클 점유 스택"이다.** 경쟁자들은 전원 단일 시점(출국·송금·채용·사건)만 잡는다. 우리는 입사→재직→출국을 하나의 데이터 파이프라인으로 점유하는 **엣지 서비스 6개(E1~E6)** 를 가져가야 하며, 이 6개는 단품이면 앱이고 묶이면 해자다.

| # | 엣지 서비스 | 층 | 무력화 대상 | 시장 상태 |
|---|---|---|---|---|
| **E1** | Refund Radar — 4분절 통합 조회 + 환급 적립 대시보드 + 출국 D-180 타임라인 | 입구 | refundcheck·케이비자·HRD 관영 | 통합 화면 0건 |
| **E2** | Employer-Verified Data Loop — 기업 원장→프로필 사전채움·기업 확인·월간 freshness | 락인(원천) | 한패스·클링커즈·NICE Welko | 공급자 0 (SSOT) |
| **E3** | E-7-4 전환 스튜디오 — 점수 자동판정 + 전환 준비 체크리스트(양면) | 락인 | 자블리·행정사·K-Work | **백지 0건** (WS20) |
| **E4** | Financial Passport 신호 API — 점수 없는 동의기반 신호 리포트 | 수익화 | 한패스 대안신용·크레파스·vivisa ACSS | 재직·임금 신호 공급자 0 |
| **E5** | Rights Guard — 임금체불·산재 자가진단 + 레드플래그 전문가 라우팅 | 입구·신뢰 | (정부 채널만 존재) | **백지 전무** (WS20) |
| **E6** | Expert Partner Desk — 서류 완비 리드 패키지 B2B2B | 수익화 | 케이비자 유통망 모델 | 대행사를 고객화 = 0건 |

**설계 원리 한 줄**: 경쟁자가 "그 순간"을 파는 동안, 우리는 그 순간이 오기 전의 길목(E1·E3·E5)과 그 순간이 남기는 자산(E2→E4·E6)을 판다.

## 1. 경쟁 압력 지도 — 누가 무엇을 못 하는가 (MECE)

경쟁군 5개로 전장을 분해하면, 각 경쟁군이 구조적으로 못 하는 것이 곧 우리가 가져가야 할 서비스다.

| 경쟁군 | 대표 | 그들의 무기 | 구조적으로 못 하는 것 | 우리의 대응 엣지 |
|---|---|---|---|---|
| ① 환급·행정 대행 | refundcheck.kr(1인 행정사, E-9/H-2 출국자 POA 대행 [1차/사이트 '26.7.6]) · 케이비자(건당 대행 O2O) | 자격(행정사)·처리 신뢰 | 출국 전 접점 없음·1건으로 관계 종료·비축적형 | **E1**(검색 이전 인터셉트) + **E6**(그들을 고객화) |
| ② 송금계 핀테크 | 한패스(JB 연합·대출비교 '26.2)·GME·센트비 | MAU·송금 행태 데이터·다국어 CS | 고용주 검증 재직·임금 원천 없음(자기신고·행태뿐) | **E2** + **E4**(신호 공급자 포지션) |
| ③ B2C 슈퍼앱 | 클링커즈 glow("Migrant Workforce OS" 표방) | 15~17개 언어·대출중개 등록 | B2B 기업 원장·준법 기능 미출시, 수익이 B2C 중개에 묶임 | **E2** + **E4** (+**E5**로 신뢰전 우위) |
| ④ HR·비자 신생 | 자블리(워치 1순위)·하이어비자(유학생 축 1위) | AI HR 표방·대학 채널 | E계열 재직 준법 깊이·금융 연결 모두 미보유 | **E3** 선점 + VisaDesk 준법 코어(7축) |
| ⑤ 관영 | HRD(보험 찾아주기)·NPS·K-Work·socinet | 공신력·무료 | 기관별 사일로·다국어 개인화·기업측 의무 관리 없음 | **E1·E3을 "정부 보완재"로** — 경쟁 금지 |

- ①의 실체 확인: refundcheck.kr = 정책관찰소(행정사 김대경, 법무부 등록 대리인 24112001076)의 웹 전면. 연금 반환일시금·퇴직금 차액·출국만기/귀국비용보험 4항목, 영/한 2개 언어 [1차/사이트 '26.7.6 — 본 문서로 경쟁 지도 신규 등재].
- ⑤가 최대 꼬리 리스크: 정부가 통합 조회를 직접 제공하면 E1 가치가 급감한다. 그래서 **E1에 과투자 금지, 진짜 보루는 E2·E4** — 빌드 순서(§5)에 반영했다.

## 2. 엣지 서비스 6개 상세 설계

각 서비스는 ⓐ정의 ⓑ작동 방식 ⓒ왜 못 따라오나 ⓓ법적 경계 ⓔ검증 KPI 5요소로 설계한다.

### E1. Refund Radar — "떠나기 전에 이미 계산돼 있는 내 돈"

- **정의**: 연금 반환일시금+퇴직금+출국만기/귀국비용보험+세금의 **4분절 통합 조회**(SSOT 확정 서사: "통합 조회 애그리게이터") + 재직 중 실시간으로 쌓이는 **환급 예상액 대시보드** + 비자 만료 기준 **출국 D-180 타임라인**(순차 체크리스트·다국어 알림).
- **작동 방식**: VisaDesk 원장에서 비자 만료일·보험 가입월·연금 납부이력을 사전 보유 → 근로자가 검색하기 전에 D-180/D-90/D-30 선제 알림 → 조회·서류 준비까지 앱에서, 신청은 본인 직접(공식 채널 라우팅) 또는 E6 전문가 라우팅.
- **왜 못 따라오나**: 대행업체는 근로자가 출국 직전 검색하는 순간을 광고비로 사야 하지만(경쟁 심한 SEO/커뮤니티), 우리는 입사 첫날부터 그 근로자를 알고 있다(CAC 0). "실시간 적립 대시보드"는 재직 데이터가 없으면 물리적으로 만들 수 없다.
- **법적 경계**: 조회·안내·서류준비는 참고정보, 신청 대행은 행정사법 영역 → 직접 대행 금지, E6로 라우팅. HRD 관영 "찾아주기"와 중복 서사 금지(단일 발굴 아닌 통합 화면). 예상액은 **[추정] 상시 표기·확정/보장 표현 금지**(WS22 #8 — 세무사법 '26.6 오인광고 금지 크로스레퍼런스).
- **KPI**: 조회 완료율 / D-180 알림 오픈율 / 환급예상액 노출 유저의 월 잔존율(락인 검증) / 관영 채널 라우팅 클릭률(보완재 증빙).

### E2. Employer-Verified Data Loop — 모든 엣지의 원천 (엣지의 엣지)

- **정의**: VisaDesk 기업 원장 → 근로자 BackWon 프로필 **사전 채움**(재직·근속·급여·비자·보험) → **기업 확인 버튼**(사업주가 월 1회 원클릭 검증) → **월간 freshness**(재직 유지·급여 변동·만료 임박 자동 갱신).
- **작동 방식**: 기업이 준법 목적으로 입력·유지하는 데이터가, 근로자 동의를 거쳐 근로자 자산(프로필·증빙 월렛)으로 전환된다. 기업에는 완료/위험 플래그만, 금융권에는 동의 범위 내 리포트만(passport-moat §7-4 데이터 계약 원칙).
- **왜 못 따라오나**: 한패스·클링커즈의 데이터는 자기신고+행태다. 금융권이 원하는 건 "기업과 근로자 양쪽에서 검증된 최신 신호"(passport-moat 해자 1·3). 이걸 만들려면 B2B 준법 SaaS를 먼저 팔아야 하는데, 그건 그들 DNA·수익모델과 상충한다.
- **법적 경계**: 고용주는 데이터 판매자가 될 수 없다(신용정보법·이익귀속 — SSOT). 동의 주체는 항상 근로자 본인, 기업은 "확인자" 역할만.
- **KPI**: 기업 확인 데이터 비중 60%+ / 월간 업데이트율 50%+ / 프로필 사전채움→근로자 활성화 전환율.

### E3. E-7-4 전환 스튜디오 — 시장 백지 1호의 선점

- **정의**: E-9→E-7-4 숙련전환 **점수 자동판정**(소득·경력·한국어·지역 가점 등 다축) + 부족 점수 로드맵("한국어 1단계 더 = +X점") + **본인 제출용 전환 준비 체크리스트**(대외 표기 — "서류 작성 서비스" 오인 방지, WS22 #1) + 기업용 뷰("전환 가능 인력 N명 — 핵심 인력 유지 플랜").
- **작동 방식**: E2 원장 데이터(근속·소득·사업장)로 판정의 70%가 자동 채워짐 → 근로자는 잔여 항목만 입력 → 판정 결과를 기업·근로자가 함께 봄 → 제출은 본인 직접 또는 **출입국민원 대행기관으로 등록된 행정사·변호사**(일반·기술·번역행정사 불가 — E6 파트너 온보딩 요건, 출입국관리법 §79의2·WS22 #2).
- **왜 못 따라오나**: WS20 전수판정 결과 유료 상품화 **0건**(정부 K-Work는 접수처, 민간은 콘텐츠뿐). 자블리가 선언한 방향이지만 E계열 제조 현장의 원장 데이터가 없다. 점수제 제도화(107개 지역)는 명시적 정책 순풍.
- **법적 경계**: 자동판정·안내는 참고정보(면책 명시), 서류 작성·제출 대행은 행정사법 → 패키지는 "본인 제출용 준비물 정리"까지, 대행 필요 시 E6 라우팅. regulatory-risk-agent 사전 점검 필수(WS20 §7 플래그).
- **KPI**: 판정 완료 수 / 기업 애드온(Growth→Compliance 업셀) 전환율 / 판정→전문가 라우팅 전환율(단 fee 산정 근거로 사용 금지 — WS22 #7). **양면 retention 레버**: 근로자는 "더 오래 남기", 기업은 "숙련 인력 유지" — VisaDesk 구독 유지의 실질 근거.

### E4. Financial Passport 신호 API — 수익 엔진 (상세: passport-moat 문서)

- **정의**: 점수·등급 없이 **동의 기반 재직·소득·체류 검증 신호**를 표준 스키마(`employment_verified`·`salary_continuity_3m`·`visa_validity_months` 등 12필드)로 금융권에 제공. 동의센터(금융사별·필드별 동의/철회)+감사로그 포함.
- **작동 방식·해자·BM**: `handoff/backwon-financial-passport-moat.md`의 해자 8개·Phase 1~2.5 설계를 그대로 따른다(중복 기술 생략). 요지: E2가 원천, ForeignID가 동의·증적, E1·E3·E5가 근로자가 매달 돌아올 이유를 만들어 동의율·freshness를 유지한다.
- **왜 못 따라오나**: 한패스의 송금 행태 데이터로는 "고용주가 검증한 재직·임금"을 못 만든다(모델 실심사 반영도 [미확인] — SSOT '26.7 톤). vivisa×클링커즈 ACSS는 제품 미출시·적용 0건. JB 비대면 계좌개설 교착('26.3)이 이 신호의 정책 수요를 방증.
- **법적 경계**: 자체 점수 산출 금지(신용정보법 본허가 회피 — SSOT 확정). CB 제휴형/은행 내부모형형 경로(passport-moat Phase 2.5).
- **KPI**: 금융권 유료 PoC 의향 1곳+ / 실심사 희망 필드 5개+ / 근로자 제공 동의율 30%+ / **금융연계 attach 15%(BEP — 단위경제 생사 변수)**.

### E5. Rights Guard — 신뢰 앵커이자 두 번째 백지

- **정의**: 임금체불·부당공제·산재 **다국어 셀프 체크**(대외 명칭 — "진단·판정"형 표현은 공인노무사법 §27② 오인 광고 소지, 결과 문구는 사실 대조형 표준 세트 사용, WS22 #3; 급여 셀프 체크와 데이터 공유) → 레드플래그 시 노무사·변호사 라우팅 → 진행상태 **표시·일정 알림·전달 로그**(사건 내용 관여 금지 — WS22 #4).
- **작동 방식**: E2의 급여 신호와 근로자 입력(실수령액·근로시간)을 대조 → 이상 감지 시 "정부 무료 채널(1350·법률구조공단) 우선 안내 + 전문가 연결 선택지" 제공.
- **왜 못 따라오나**: WS20 판정 — 민간 디지털 서비스 **전무**(정부 채널은 오프라인·전화·한국어 장벽). 고용주 채널로 유입되는 서비스가 근로자 권익을 지켜준다는 역설이 신뢰를 만든다 → "내 데이터가 팔린다"는 불신을 상쇄하는 **동의율 해자 장치**(passport-moat 해자 4의 실행 수단).
- **법적 경계**: 진단·안내까지만, 수임·대리는 노무사법·변호사법 → 라우팅만. 기업 고객과의 이해충돌 설계 필요: 기업에는 개별 신고 내용이 아니라 "익명 리스크 플래그"만 노출.
- **KPI**: 셀프 체크 완료→라우팅 전환율 / 사용자 NPS / 동의율(E5 사용자 vs 미사용자 비교 — 신뢰 가설 검증). E5 자체는 무료 유지(간접 대가로 변§109 유상성 구성 여지는 [확인필요] — WS22 §5-7).

### E6. Expert Partner Desk — 대행사를 경쟁자에서 고객으로

- **정의**: 행정사·노무사에게 **"사전 정리 서류 패키지(Document-Ready Package)"**(동의된 재직·임금·보험 증빙 사전 정리 + 다국어 커뮤니케이션)를 공급하는 B2B2B 데스크. E1·E3·E5에서 발생하는 대행 수요의 출구. 대외·계약 문서에서 "리드" 표현 금지(알선 서사의 정황 증거 — WS22 #5, 내부 분석 용어로만).
- **작동 방식**: 근로자가 대행을 선택 → 동의 범위 내 서류 패키지가 파트너 전문가에게 전달 → 전문가는 서류 수집(통상 처리시간의 상당 부분)을 생략하고 심사·제출만 → 처리 리드타임 단축분이 파트너의 지불 이유.
- **왜 못 따라오나**: 케이비자의 "파트너스 100~300"은 접수처 유통망이지 데이터 자산이 없다. 우리는 반대로 **데이터(서류 완비)를 들고 전문가망을 유통망으로 흡수**한다 — refundcheck 같은 1인 행정사가 잠재 고객이 되는 구조. 전문가 네트워크(행정사 3,360·변호사 365 — SSOT)가 경쟁자가 아니라 채널이 된다.
- **법적 경계**: 점검 완료(WS22 건3 🟡 조건부) — **서류 정리·번역·전달 용역 fee**로 설계하되 4조건(수임 여부와 무관한 부과 · 용역 실질 · 성공보수 절연 · 특정 전문가 유인 배정 금지)을 계약에 명문화. 성공보수 연동·수임액 비례·수임 조건부 건당 과금은 🔴(강남언니 2심 유죄 vs 로톡 정액 광고 무혐의 구도). 전달 증빙은 개보법 §17② 5요소 고지+§24① 고유식별정보 별도 동의+다국어 동의 필수.
- **KPI**: 파트너 전문가 수 / 패키지 건당 fee 수용가 / 패키지 완결성·처리 리드타임 단축률(가치 증빙) / 파트너 재구매율. (수임 전환율은 내부 리서치 지표로 격리 — 대외 공표·fee 협상 사용 금지, WS22 #6)

## 3. 왜 6개가 묶여야 하는가 — 스택 구조

```
[수익화]   E4 신호 API (금융권 조회료·attach)     E6 파트너 데스크 (전문가 fee)
              ▲ 동의·freshness                        ▲ 대행 수요
[락인]     E2 고용주 검증 루프 (원천 데이터) ←→ E3 전환 스튜디오 (체류 연장 = 데이터 수명 연장)
              ▲ 등록·동의                              
[입구]     E1 환급 레이더 (돈)          E5 권익 가드 (신뢰)          급여진단 (기존)
              ▲ CAC 0
[기반]     VisaDesk 구독(B2B 현금흐름) + ForeignID(동의·인증·감사로그)
```

- **E1·E5 없이 E4만**: 동의율이 안 나온다(내 데이터를 왜 주나). — passport-moat 해자 4.
- **E2 없이 E1·E5만**: refundcheck·글로우가 카피 가능한 "조회 앱"이 된다. 축적이 없다.
- **E3 없이**: 데이터 수명이 근로자 체류기간에 갇힌다. 전환 성공 = 고객 수명 3~5년 연장 = freshness 해자 연장.
- **E6 없이**: 대행 수요가 외부(경쟁 대행사)로 유출되고 우리는 리퍼럴 소액만 남는다.
- 단품이면 앱, 묶이면 해자(passport-moat §8 결론과 동일 논리) — 이 설계도의 존재 이유다.

## 5. 빌드 시퀀스 — 무엇을 언제

| 단계 | 빌드 | 목적 | go/no-go 기준 [목표·가정] |
|---|---|---|---|
| **PoC 8주** | E2 최소 루프(등록→초대→기업 확인 버튼) + E1 조회 v0(연금·퇴직금 2분절 우선) + E4 샘플 리포트(RFI용 정적 문서) + E3 판정 로직 프로토타입(엑셀→웹) | 데이터 권리 증명(Proof of Data Right) | 근로자 프로필 50명+ / 동의율 30%+ / 기업 확인 응답률 측정 개시 |
| **~12M** | E3 정식(기업 애드온) + E4 유료 PoC 1곳 + E5 자가진단 v1 + E6 파일럿(행정사 5곳) + E1 4분절 완성 | 금융 WTP·전문가 WTP 증명 | 금융권 유료 PoC 1곳+ / 유효 필드 5개+ / E6 건당 fee 수용 확인 |
| **~24M** | E4 API 구독 전환 + 표준 스키마 2~3사 공동검증 + E6 확장(행정사 30곳+) + 월간 freshness 자동화 | 해자 증명(Proof of Moat) | 월간 업데이트율 50%+ / 기업확인 비중 60%+ / **attach 15%**(미달 시 BM 재설계 — 환급·대행 어느 쪽도 단독 흑자 불가가 기존 판정) |

- 순서의 논리: **E2가 항상 먼저다**(모든 엣지의 원천). E1은 "가장 싼 입구"라서 8주에 포함하되 2분절로 절제(관영 리스크). E4는 8주엔 "팔지 말고 물어본다"(RFI). E3는 정책 순풍+백지라 12M 내 정식 출시가 자블리 대비 타이밍 방어.
- 실패 시 대안: 동의율 30% 미달 → E5·E1 가치 보강 후 재측정(금융 서사 후퇴). 기업 확인 응답 저조 → 확인 부담을 분기 1회로 낮추고 freshness 필드 축소. attach 15% 미달 → E6(전문가 fee)·VisaDesk 구독 중심으로 BM 무게 이동.
