# PlugNX B2C-first → B2B Pull-through 사업기획서

> 작성일: 2026-06-17  
> 목적: BackWon을 B2C 진입 웨지로 삼아 VisaDesk B2B로 전환하고, ForeignID 기반 금융 신뢰 인프라로 확장하는 실행 기획  
> 결론: **B2C-first로 시작하되 B2C-only가 아니라, 외국인 개인의 환급·금융 니즈가 회사 확인 요청을 만들고 그 요청이 VisaDesk B2B 리드로 전환되는 구조를 설계한다.**

---

## 1. Executive Summary

PlugNX의 외국인 신사업은 처음부터 기업용 재직관리 SaaS를 팔러 다니는 방식보다, **외국인 개인이 먼저 들어오는 모바일 웹 기반 BackWon 진단 플로우**를 입구로 삼는 편이 더 자연스럽다.

외국인 개인은 "내가 받을 수 있는 돈", "한국에서 가능한 대출·계좌·송금 혜택", "내 체류·재직 상태로 금융 이용이 가능한지"를 확인하고 싶어한다. 이 과정에서 정확한 결과를 얻으려면 회사의 재직·급여·체류 확인이 필요하다. 이때 발생하는 **회사 확인 요청**이 VisaDesk의 B2B 리드가 된다.

따라서 사업의 핵심 흐름은 다음과 같다.

```text
BackWon 모바일 웹 진단
  → ForeignID L1/L2 인증
  → 환급·금융·체류 가능성 결과
  → 회사 확인 요청
  → 회사가 VisaDesk 무료 관리공백 리포트 확인
  → 유료 VisaDesk 구독 전환
  → 동의 기반 Foreign Worker Trust Profile 축적
  → 케이뱅크 등 금융권 PoC·제휴
```

이 전략은 "앱 설치"나 "방문영업"이 아니라, **외국인 개인의 문제 해결 행동이 기업 영업과 금융 데이터 검증으로 자동 전환되는 인프라**를 만드는 전략이다.

## 2. 왜 B2C-first인가

### 2-1. B2B-first의 한계

| 한계 | 설명 |
|---|---|
| 구매 필요성 설명이 어렵다 | 기업 입장에서는 "엑셀·카톡·행정사로도 할 수 있지 않나?"라고 생각할 수 있다. |
| 방문영업 비용이 크다 | 산단·제조기업을 일일이 찾고 설명해야 하며, 초기 CAC가 높다. |
| SaaS 기능만으로 해자가 약하다 | 비자 만료 알림, 서류 체크리스트는 ERP·HR SaaS가 추가 개발할 수 있다. |
| 직원 니즈가 보이지 않는다 | 기업만 보면 외국인 근로자의 환급·금융 니즈와 데이터를 확보하기 어렵다. |

### 2-2. B2C-first의 장점

| 장점 | 사업적 의미 |
|---|---|
| 가입 명분이 쉽다 | "내가 받을 수 있는 돈 확인"은 설명이 짧고 즉시적이다. |
| 웹 유입이 가능하다 | 검색, 커뮤니티, 지인 공유, QR, 송금사/은행 제휴 링크로 진입 가능하다. |
| 회사 확인 요청이 생긴다 | 환급·대출·재직 확인을 위해 자연스럽게 회사 담당자에게 링크가 간다. |
| 은행 데이터 PoC가 가능하다 | 개인 동의 기반으로 체류·재직·소득·환급 신호를 구조화할 수 있다. |
| 대기업 재직자도 잡힌다 | 대기업에는 VisaDesk를 팔기 어렵지만, 개인 환급·금융 진단은 여전히 가능하다. |

핵심은 B2C로 끝내는 것이 아니다. **B2C를 B2B 리드 생성 엔진으로 설계해야 한다.**

## 3. 제품 정의

### 3-1. 한 줄 정의

| 제품 | 한 줄 정의 | 시작 형태 |
|---|---|---|
| BackWon | 외국인 근로자의 환급·급여·금융 가능성을 확인하는 모바일 웹 진단 서비스 | 모바일 웹/PWA |
| VisaDesk | 회사가 외국인 직원의 체류·재직·서류·금융 확인 요청을 관리하는 B2B 콘솔 | PC 웹 SaaS |
| ForeignID | 외국인 개인의 본인확인·동의·체류·재직 신뢰도를 표준화하는 인증 레이어 | 공통 인프라 |
| Trust Profile | 은행이 볼 수 있는 동의 기반 외국인 근로자 신뢰 신호 | 금융권 PoC 산출물 |

### 3-2. 초기 제품은 앱이 아니라 웹이다

| 사용자 | 1차 채널 | 이유 |
|---|---|---|
| 외국인 근로자 | 모바일 웹/PWA | 검색·커뮤니티·QR·지인 공유로 즉시 진입해야 한다. |
| 회사 담당자 | PC 웹 SaaS | 직원 명단, 서류, 리포트, 알림, 권한 관리가 필요하다. |
| 현장 관리자 | 모바일 웹 | 서류 사진 업로드, 직원 확인, 간단 승인에 적합하다. |
| 금융 파트너 | 리포트/API 샘플 | 초기에는 실시간 API보다 PoC용 요약 신호가 적절하다. |

앱은 초기 필수조건이 아니다. 앱은 문서지갑, 전자서명, 송금, 대출 실행, 반복 푸시 알림이 검증된 뒤 확장한다.

## 4. 핵심 고객 여정

### 4-1. 외국인 개인 여정

| 단계 | 사용자가 하는 일 | PlugNX가 얻는 것 |
|---|---|---|
| 1. 진입 | "외국인 환급", "국민연금 반환", "외국인 대출" 검색 또는 링크 클릭 | 익명 방문자 |
| 2. 1분 진단 | 국적, 비자, 재직기간, 월급, 회사명, 출국 예정 여부 입력 | 환급·금융 니즈 데이터 |
| 3. ForeignID L1 | 여권+셀카 또는 기본 본인확인 | 기본 신뢰 레벨 |
| 4. 결과 확인 | 환급 가능성, 체류 D-day, 금융 사전확인 결과 열람 | 사용자 전환 |
| 5. 회사 확인 요청 | "정확한 결과를 위해 회사 확인 요청" 클릭 | B2B 리드 발생 |
| 6. 금융 혜택 신청 | 케이뱅크 등 제휴 금융 혜택 사전확인 동의 | 은행 PoC 샘플 |

### 4-2. 회사 담당자 여정

| 단계 | 회사가 보는 것 | VisaDesk 전환 포인트 |
|---|---|---|
| 1. 직원 요청 수신 | "귀사 외국인 직원 3명이 재직/급여 확인을 요청했습니다." | 직원발 Pull 리드 |
| 2. 회사 인증 | 사업자 정보·담당자 이메일·전화 확인 | 회사 Claim Page 생성 |
| 3. 무료 리포트 | 체류만료, 누락서류, 환급/금융 문의 유형 요약 | 관리 공백 시각화 |
| 4. 직원 명단 업로드 | 엑셀 또는 간단 입력 | VisaDesk 데이터 원장 시작 |
| 5. 유료 전환 | 알림, 문서함, 리포트, 담당자 권한, 월간 점검 | Starter/Growth/Compliance 플랜 |

### 4-3. 금융 파트너 여정

| 단계 | 은행이 받는 것 | 목적 |
|---|---|---|
| 1. PoC 샘플 | 익명/가명 처리된 Trust Profile 구조 | 심사 활용 가능성 판단 |
| 2. 변수 검토 | 체류기간, 재직기간, 급여 안정성, 회사 확인 여부, ForeignID 레벨 | 유효 신호 선별 |
| 3. 공동 랜딩 | 외국인 금융혜택 사전확인 | 적격 리드 확보 |
| 4. 제휴 모델 선택 | 리드 제휴, KYC Pack, 재직확인 API, Trust Signal | 사업화 |

## 5. 자동 세일링 인프라 설계

### 5-1. Growth Loop 1: 환급 진단 → 회사 확인 요청

```text
외국인 개인이 환급 가능성 진단
  → 회사 확인 시 정확도 상승 안내
  → 담당자에게 확인 요청 링크 발송
  → 회사가 무료 리포트 확인
  → VisaDesk 가입
```

핵심 CTA:

> 회사 확인을 받으면 환급·금융 가능성 진단이 더 정확해집니다. 담당자에게 확인 요청을 보낼까요?

### 5-2. Growth Loop 2: 금융 사전확인 → 회사 신뢰 데이터

```text
외국인이 금융 혜택 사전확인
  → 체류·재직·급여 확인 필요
  → 회사가 재직확인
  → 은행 제출용 Trust Profile 생성
  → 회사는 직원 금융복지 리포트 확인
```

핵심 메시지:

> 회사가 재직확인을 해주면 외국인 직원의 금융 혜택 사전확인 가능성이 높아집니다.

### 5-3. Growth Loop 3: 동료 추천

```text
사용자가 환급/대출/체류 결과 확인
  → 같은 회사·같은 국적 동료에게 공유
  → 회사 단위 요청 수 증가
  → 담당자에게 "직원 요청 묶음" 전달
```

핵심 기능:

- 회사명 기반 같은 사업장 요청 묶기
- 국적/언어별 공유 링크
- "같은 회사 직원 5명이 확인했습니다" 같은 사회적 증거

### 5-4. Growth Loop 4: 전문가/파트너 역소개

```text
행정사·노무사·송금사·은행이 BackWon 진단 링크 공유
  → 외국인 개인 유입
  → 회사 확인 요청 발생
  → 파트너에게 리드/상담 기회 환류
```

## 6. 데이터 설계

### 6-1. 단계별 데이터 수집 원칙

| 단계 | 수집 데이터 | 원칙 |
|---|---|---|
| 익명 진단 | 국적, 비자, 재직기간, 월급 범위, 출국 예정 여부 | 개인식별정보 없이 시작 |
| 가입 | 이름, 연락처, 선호 언어, 회사명 | 최소 정보 수집 |
| ForeignID L1 | 여권+셀카 또는 대체 본인확인 | 기본 신원 확인 |
| ForeignID L2 | 외국인등록증, 통신 인증, 체류 정보 | 체류·연락 검증 |
| ForeignID L3 | 계좌, 전자서명 | 금융거래·전자계약 단계에서만 |
| 회사 확인 | 재직 여부, 급여 확인, 계약 상태, 담당자 확인 | 회사 동의와 근로자 동의 분리 |

### 6-2. Trust Profile 표준 필드

| 카테고리 | 필드 예시 | 은행 활용 가능성 |
|---|---|---|
| Identity | ForeignID 레벨, 본인확인 일자 | KYC 보조 |
| Visa Stability | 체류자격, 체류만료 D-day, 연장 필요 여부 | 대출기간/체류기간 정합성 |
| Employment | 재직 여부, 근속개월, 계약 형태, 회사 확인 여부 | 상환능력 보조 신호 |
| Income | 월급 범위, 급여 안정성, 급여명세/입금 확인 여부 | 소득 안정성 |
| Employer Trust | 사업장 확인 여부, 직원 요청 수, 서류 응답률 | 사업장 신뢰도 |
| Refund Potential | 국민연금·퇴직금·보험 등 환급 가능성 | 미래 현금흐름 후보 |
| Consent | 동의 범위, 제공처, 철회 가능 여부 | 개인정보·신용정보 컴플라이언스 |

주의: 초기에는 "신용점수"라고 부르지 않는다. **Trust Profile / Eligibility Signal / 사전확인 신호**로 표현한다.

## 7. PoC 로드맵

### 7-1. 0~2주: B2C 진단 MVP

| 과제 | 산출물 | 성공 기준 |
|---|---|---|
| 모바일 웹 진단 플로우 | 환급·금융·체류 1분 진단 | 진단 완료율 40% 이상 |
| 회사명 입력 UX | 회사명/지역/업종 입력 | 회사명 입력률 40% 이상 |
| 회사 확인 요청 | 담당자 링크 전송 기능 | 확인 요청률 15% 이상 |
| 언어 지원 | 한국어+영어+베트남어 우선 | 주요 유입 언어별 이탈률 확인 |

### 7-2. 3~4주: 회사 Claim Page

| 과제 | 산출물 | 성공 기준 |
|---|---|---|
| 회사 요청함 | 직원 요청이 쌓이는 회사 페이지 | 회사 응답 10곳 |
| 무료 관리공백 리포트 | 체류·서류·환급·금융 문의 요약 | 리포트 열람률 60% 이상 |
| 직원 명단 업로드 | 엑셀 업로드 또는 수기 입력 | 5개 회사 이상 데이터 제공 |
| 리드 스코어링 | 유료 전환 가능성 분류 | 유료 상담 3건 이상 |

### 7-3. 5~8주: VisaDesk 유료 PoC

PROJECT.md 기준 PoC 목표는 **8주 15사 · 3,300만원**이다.

| 과제 | 산출물 | 성공 기준 |
|---|---|---|
| 15사 PoC | 산단·제조·서비스 외국인 고용기업 | 15사 참여 |
| 300명 B2C 가입 | BackWon 진단 완료 외국인 | 300명 이상 |
| 6사 유료 전환 | Starter/Growth 중심 | 6사 이상 |
| 은행 샘플 리포트 | 케이뱅크 검토용 Trust Profile | 100건 이상 |

### 7-4. 3~6개월: 제휴·반복 사용 검증

| 과제 | 설명 |
|---|---|
| 케이뱅크 PoC | 대출 실행 전, 신호 유효성 검증부터 진행 |
| 송금사/커뮤니티 제휴 | 한패스·센트비 등은 B2C 유입 채널 후보 |
| 행정사/노무사 패널 | 회사 리포트의 신뢰도 보강 |
| 월간 리포트 자동화 | 회사가 매월 열어보는 리포트로 사용 빈도 확보 |

### 7-5. 6~12개월: B2B SaaS 확장

| 과제 | 설명 |
|---|---|
| VisaDesk Growth 플랜 강화 | 월 89만원을 기본 랜딩 플랜으로 설계 |
| ERP/급여대장 연동 검토 | 더존·급여 엑셀·출퇴근 데이터 연동 |

| 확장 | 설명 |
|---|---|

## 14. 최종 포지셔닝 문장

PlugNX는 외국인 재직관리 SaaS를 먼저 파는 회사가 아니다.  
**BackWon으로 외국인 개인의 환급·금융 니즈를 모으고, 그 과정에서 발생하는 회사 확인 요청을 VisaDesk B2B로 전환하며, ForeignID로 본인확인·재직·체류·소득 신뢰 신호를 표준화하는 외국인 금융·재직 인프라**다.

따라서 시장 진입 순서는 다음이 맞다.

```text
1. 모바일 웹 BackWon 진단
2. 회사 확인 요청
3. VisaDesk 무료 관리공백 리포트
4. VisaDesk 유료 구독
5. 케이뱅크 등 금융권 Trust Profile PoC
6. ForeignID 기반 금융 인프라 확장
```
