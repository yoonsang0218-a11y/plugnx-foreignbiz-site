## 0. 결론 먼저

**재검토 판정: BackWon은 "환급 대행 사업"으로는 NO, "VisaDesk가 만든 고용·재직·임금 데이터 위에 근로자 동의를 붙여 금융권에 연결하는 데이터/신호 레이어"로는 조건부 GO.**

이번 재검토에서 3자 workflow를 실제 프로세스로 쪼개면 답이 선명해진다.

1. **사업자 workflow는 BackWon 직접 과금이 아니라 VisaDesk retention·upsell workflow다.** 사업자에게 현금으로 바로 돌아오는 환급은 출국만기보험 1년 미만 사용자 수령분 정도다. 나머지는 외국인 고용 점수·보험·고용변동신고·E-7-4 전환·K-Trust 예정 대응 같은 비현금 준법/자격 유지 가치다.
2. **재직자 workflow는 "받을 돈 확인"보다 "동의와 신뢰 획득"이 핵심이다.** 국민연금 반환일시금·출국만기보험·귀국비용보험·퇴직금·세금은 모두 가능성 진단과 공식/전문가 라우팅으로만 안전하게 처리해야 한다. 플랫폼이 직접 대행·성공보수·세금환급을 전면에 세우면 규제 리스크가 커진다.
3. **금융권 workflow가 BM의 생사다.** 은행·CB·송금사는 외국인 thin-file 문제를 풀 신호가 필요하지만, BackWon이 직접 신용점수·대출중개·송금업을 하면 인허가 영역으로 들어간다. 안전한 길은 **근로자 동의 기반의 검증 재직·임금 신호 API/리포트 + 등록 금융사 송객**이다.

**따라서 BM 구조는 아래처럼 고정해야 한다.**

| BM 축 | 판정 | 이유 |
|---|---:|---|
| VisaDesk B2B 구독/상향 | **Main** | 사업자 지불은 VisaDesk에서 발생. BackWon은 복지·준법·정산 부가가치로 retention/upsell 보강 |
| 금융사 송객 CPA | **Short-term** | 등록 금융사·송금사·카드사로 연결. 단가와 전환율은 RFI/파일럿 필요 |
| 동의기반 고용·임금 신호 라이선스 | **Mid-term / 핵심 업사이드** | right-to-win의 중심. 단 신용정보법·CB/은행 지불의사 검증 전 BM 확정 금지 |
| 환급/정산 전문가 연결 | **Small / 보조** | 자격사법 때문에 고마진 직접 과금 불가. 건당 공헌 작고 1회성 |
| 직접 송금·대출·신용점수·세금환급 | **NO-GO** | 외국환거래법·금소법·신용정보법·세무사법 인허가/자격 영역 |

## 1. 3자 Process Map

### 1.1 전체 흐름

```text
사업자(VisaDesk)
  └─ 근로자 등록·초대
      └─ 재직자(BackWon/ForeignID)
          ├─ 환급·정산 가능성 진단
          ├─ 급여·보험·체류 데이터 확인
          └─ 금융 정보제공 동의
              └─ 금융권(은행·CB·송금·카드)
                  ├─ 등록 금융상품 송객
                  └─ 동의기반 재직·임금 신호 조회/리포트
```

**핵심 통제점:** 사업자 데이터만으로 금융권에 넘기면 안 된다. 반드시 근로자 본인의 별도 동의, 목적 고지, 제공 범위, 철회권, 보관기간이 필요하다.

### 1.2 데이터와 돈의 흐름

| 흐름 | 데이터/가치 | 돈의 방향 | 제품 경계 |
|---|---|---|---|
| 사업자 → PlugNX | 근로계약, 체류자격, 임금, 보험가입, 고용변동 | 사업자 → VisaDesk 구독료 | B2B 준법 SaaS |
| 재직자 → PlugNX | ForeignID, 본인 동의, 환급·급여 조회 입력 | 원칙 무료. 일부 전문가 수수료는 자격자에게 | B2C 신뢰·동의 획득 |
| PlugNX → 금융권 | 점수 자체가 아닌 검증 신호/리포트 | 금융권 → PlugNX CPA/API료 `[확인필요]` | 등록 금융사·CB 제휴 |
| 금융권 → 재직자 | 대출·카드·송금·계좌 상품 | 재직자/금융권 간 거래 | PlugNX 직접 금융업 금지 |
| PlugNX → 사업자 | 준법 리포트, 정산 알림, 전환자격 | VisaDesk retention/upsell | BackWon 직접 과금 아님 |

## 2. 사업자 Workflow

### 2.1 사업자 프로세스

```text
1. VisaDesk 계약
2. 외국인 근로자 등록: 비자, 근로계약, 임금, 보험, 체류만기
3. BackWon 초대: 무료 복지/출국정산 안내로 권유
4. 재직 중 관리:
   - 보험가입·고용변동신고 기한 알림
   - 최저임금/임금체불/퇴직금 차액 리스크 점검
   - E-7-4 전환·점수제·K-Trust 준비도 관리
5. 퇴사·출국:
   - 1년 미만 출국만기보험 사용자 수령분 알림
   - 1년 이상 근로자 출국만기보험·퇴직금 차액 정산
6. 결과:
   - 처벌/분쟁 회피
   - 다음 외국인력 배정 점수 관리
   - VisaDesk 상위 플랜 전환 명분
```

### 2.2 사업자 가치 재판정

| 가치 | 확인 결과 | BM 함의 |
|---|---|---|
| 출국만기보험 1년 미만 사용자 수령 | `[1차/2차]` 확인. 사용자에게 돌아가는 거의 유일한 직접 현금 훅 | VisaDesk "미청구 정산 알림" 기능. 다만 고회전 사업장에 더 잘 맞아 ICP와 충돌 가능 |
| 보험·고용변동·체불 제재 회피 | `[1차]` 보험가입, 신고, 점수제 감점 구조 확인 | VisaDesk 본가치. BackWon은 정산·급여 데이터로 보강 |
| E-7-4/E-7-4R 숙련전환 | `[1차]` 추천·점수제·지역특화 전환 통로 확인 | 숙련제조/요양 세그먼트 핵심 upsell 명분 |
| K-Trust | `[1차]` 2030 전략에 도입 예정·체류연장 자동승인 등 예고. 세부는 미공개 | "시행 예정"으로만 표현. 혜택 단정 금지 |
| 근속·채용력 개선 | `[추정]` 페인은 실재하나 BackWon 귀속 효과 미검증 | PoC 인터뷰·파일럿으로만 검증 가능 |
| ESG | `[추정]` 중소 ICP 구매 트리거로 약함 | 영업 전면 문구에서 제외 |

### 2.3 사업자 BM 결론

**사업자는 BackWon에 따로 돈을 내지 않는다.** 사업자 지불은 VisaDesk 구독료로만 받아야 한다.

구체적으로는:
- Starter/Growth에는 기본 초대·정산 체크리스트.
- Compliance에는 근로자 금융·급여·환급 케어 리포트, 보험/퇴직금 차액 경고, E-7-4/K-Trust 준비도, 점수제 감점 리스크를 fence로 둔다.
- "사장님 환급"을 전면에 세우면 고회전·captive 세그먼트를 끌어들일 위험이 있어, ICP는 숙련제조·요양 중심으로 유지한다.

## 3. 재직자 Workflow

### 3.1 재직자 프로세스

```text
1. BackWon 초대 수신
2. ForeignID 인증:
   L1 여권+셀카 → L2 외국인등록증/통신 → L3 계좌/전자서명
3. 본인 동의:
   - 환급 가능성 진단
   - 급여/재직 데이터 확인
   - 금융권 제공 여부 별도 동의
4. 환급·정산 진단:
   - 국민연금 반환일시금
   - 출국만기보험금
   - 귀국비용보험
   - 퇴직금/체불임금
   - 세금/연말정산은 세무사 또는 홈택스 핸드오프
5. 공식채널·전문가 라우팅:
   - NPS/보험사/EPS/고용센터/세무사/노무사/행정사
6. 금융 준비도:
   - 재직기간, 임금입금, 비자만기, 고용주 확인, 보험가입 신호 정리
   - 등록 금융사 상품 연결
```

### 3.2 재직자별 환급/정산 항목

| 항목 | 가능한 제품 표현 | 금지/주의 |
|---|---|---|
| 국민연금 반환일시금 | "가능성 진단", "NPS 공식 청구 안내", "출국 전 체크리스트" | "우리가 받아드립니다", 고정 국가목록 하드코딩 |
| 출국만기보험 | "가입·수령 대상 확인", "보험사 청구 준비" | 보험금 직접 수령·대리청구 |
| 귀국비용보험 | "본인 부담 보험금 청구 안내" | 확정 환급액 보장 |
| 퇴직금/체불 | "예상 차액 진단", "노무사/행정사 연결" | 사용자 상대 청구·교섭·분쟁대리 직접 수행 |
| 세금/연말정산 | "세무 전문가 연결", "홈택스 본인신고 안내" | "세금환급", "신고대행", "환급액 도착" 류 |
| 급여 적정성 | "참고용 급여 리포트", "확인 권고" | 법률 판단·체불 확정 표현 |

### 3.3 재직자 BM 결론

재직자에게 과금하는 구조는 약하다. 이유는 네 가지다.

1. 정부/공식 무료채널이 존재한다.
2. 자격사법 때문에 플랫폼 직접 성공보수가 제한된다.
3. 외국인 B2C 유료획득은 CAC가 높고 신뢰비용이 크다.
4. 환급은 1회성이라 LTV가 낮다.

따라서 재직자용 BackWon의 역할은 **무료 또는 저가의 신뢰 훅**이다. 수익이 아니라 동의·데이터·반복 금융연계로 이어져야 한다.

## 4. 금융권 Workflow

### 4.1 금융권 프로세스

```text
1. 금융 파트너 RFI:
   은행, CB, 카드사, 등록 대출모집법인, 등록 송금사
2. 데이터 항목 정의:
   재직확인, 임금수준, 임금입금 안정성, 고용기간, 비자만기,
   고용주 준법 상태, 보험가입, 출국/전환 가능성
3. 법률 구조 확인:
   본인 동의, 신용정보 제공 목적, 보관기간, 철회, 제3자 제공
4. 파일럿:
   - 등록 금융상품 송객
   - 점수 없는 "금융 준비도 리포트"
   - CB/은행 내부모형 입력용 신호 제공
5. 정산:
   - CPA/실행수수료
   - 건당 조회료/API료
   - PoC/월정액 라이선스
```

### 4.2 금융권 가치

| 금융권 문제 | BackWon/PlugNX 입력값 | 검증 상태 |
|---|---|---|
| 외국인 thin-file | 국내 재직·임금·고용주 확인 신호 | 수요는 강하게 보이나 유료 WTP는 미확인 |
| 체류만기/이탈 리스크 | 비자만기, 사업장, 전환 가능성 | VisaDesk 보유 가능. 제공 적법성 검토 필요 |
| 급여흐름 확인 | 임금대장/계약/입금 확인 | 은행 자행 계좌 밖의 신호라는 점이 차별점 |
| eKYC | ForeignID L1~L3 | 경쟁 성숙. 단독 해자는 약함 |
| 송금·카드·대출 전환 | B2B2C CAC 0 근로자 모수 | attach율 실측 필요 |

### 4.3 금융권 BM 결론

금융권 BM은 두 단계로 봐야 한다.

**1단계: 송객/제휴형**
- 등록 금융사·송금사·카드사로 연결.
- 수익: CPA, 실행수수료, 공동 프로모션비.
- 장점: 규제 부담이 상대적으로 낮고 빠르게 테스트 가능.
- 단점: 단가가 낮고 한패스·은행 앱 선점과 경쟁한다.

**2단계: 신호/API형**
- BackWon이 신용점수를 만들지 않고, 동의 기반 재직·임금 신호를 CB/은행에 제공.
- 수익: 건당 조회료, 월정액, PoC fee.
- 장점: PlugNX right-to-win의 중심.
- 단점: 신용정보법 적격성, 정보제공자 지위, 개인신용평가업/마이데이터 허가 회피 범위가 미확정이다.

| 2026 E-9 신규 도입 | 8만명 | `[1차/2차]` 고용허가제 정책자료·보도 | 신규 유입보다 기존 재직자 관리·전환이 중요 |
| 외국인 반환일시금 흐름 | 2024년 3,596.9억원·41,094명 보도 | `[2차]` NPS 제출자료 기반 보도 | 환급 페인은 실재하나 플랫폼 취득 가능 SOM은 제한 |
| 외국인 금융 경쟁 | NICE Welko(2026.6), 한패스 대출/송금, 은행 외국인 대출 | `[2차]` 공식/보도 | 금융연계 시장은 레드오션. 데이터 신호로 차별화해야 함 |

### 5.2 단위경제 재판정

기존 WS07 결론을 유지한다.

| 변수 | 보수적 판정 |
|---|---|
| 환급 실과금전환 | 노출/가입 60%가 아니라 실거래 3~9% 가정 |
| 환급 1건 공헌 | 0~10만원대 가정. 자격사법·무료채널 때문에 낮음 |
| 금융 attach BEP | 약 15% 가정. 이보다 낮으면 독립 P&L 약함 |
| B2C 단독 CAC | CAC > LTV 가능성이 높아 NO |
| 통합 사업성 | VisaDesk ARR이 본체, BackWon은 데이터 해자·금융 옵션 |

### 5.3 Go/No-Go

**조건부 GO 조건**

1. 금융 attach 파일럿에서 환급조회/급여진단 유저의 금융상품 연결률 **10% 이상**.
2. 은행·CB 중 **1곳 이상 유료 PoC 의향** 확보.
3. 신용정보법 법률검토에서 "점수 자체 산출 없이 동의기반 신호 제공"이 본허가 없이 가능하다는 결론.
4. NPS·보험·고용 데이터 접근 UX가 "본인 직접조회 업로드"라도 전환율을 버틸 수 있음.
5. 사업자 인터뷰에서 A/B 세그먼트(숙련제조·요양) **70% 이상 무료 권유 의향**.
6. 세무/노무/행정사 라우팅 제휴가 실제 공급 가능.

**NO-GO 또는 기능 축소 조건**

1. 금융 attach <5% + 신호 API 법률검토 부정.
2. 은행·CB 지불의사 0.
3. 자격사 제휴 전면 거부.
4. 본인조회/업로드 전환율 붕괴.
5. 고용주가 "근로자 투명화·금융자립"을 위협으로 보는 응답이 ICP에서도 높음.

## 7. 권고 실행안

### 7.1 2주 검증 스프린트

| Day | 작업 | 산출물 |
|---|---|---|

| D2~D7 | 금융권 RFI 5곳 | 유료 PoC 의향, 필요 데이터 필드, 예상 단가 |
| D4~D9 | 사업자 인터뷰 12곳 | 무료 권유율, upsell WTP, captive 역효과 |
| D5~D10 | 근로자 테스트 100명 | ForeignID→환급조회→금융동의 funnel |
| D8~D12 | 자격사·보험사·공단 확인 | 라우팅 공급, 보험 환급식, 데이터 조회 UX |
| D13~D14 | Go/No-Go 회의 | BM 확정 또는 기능 축소안 |

### 7.2 MVP 제품 경계

**MVP에 넣을 것**
- VisaDesk 근로자 초대 + 별도 동의.
- BackWon 환급 가능성 진단(추정/확인필요 라벨).
- 본인 직접조회/업로드 기반 공식 증빙 수집.
- 급여·보험·퇴직금 차액 리포트(참고용).
- 등록 금융사 송객.
- 점수 없는 금융 준비도 리포트.

**MVP에서 뺄 것**
- 직접 환급 대행.
- 세금환급/신고대행 표현.
- 직접 신용점수.
- 직접 대출중개 광고.
- 직접 송금·지갑.
- 고용주에게 금융 데이터 대가 환급/리베이트.

## 8. 최종 포지셔닝

**권장 문장**

> BackWon은 외국인 근로자가 받을 수 있는 정산·환급 가능성을 모국어로 확인하고, 본인 동의하에 검증된 재직·임금 정보를 금융권 연결에 활용하는 Foreign Worker Financial Readiness Layer다.

**금지 문장**

> 외국인 환급 대행 플랫폼, 세금환급 앱, 외국인 신용점수 제공, 대출 승인 보장, 송금 슈퍼앱.

**영업 대상별 한 줄**

| 대상 | 메시지 |
|---|---|
| 사업자 | "근로자 케어와 출국정산을 VisaDesk 안에서 관리해 준법·전환·배정 리스크를 줄입니다." |
| 재직자 | "내가 받을 수 있는 돈과 금융 준비 상태를 모국어로 확인하고, 필요한 곳은 공식기관/전문가로 연결합니다." |
| 금융권 | "은행 내부 계좌에 없는 검증 재직·임금 신호를, 근로자 동의 기반으로 제공합니다." |
