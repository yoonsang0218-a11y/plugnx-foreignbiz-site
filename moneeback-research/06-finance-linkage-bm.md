## 0. 결론 먼저 (BLUF)

**금융연계는 "환급=1회성"을 LTV로 살리는 유일한 축이지만, PlugNX가 가장 늦게 도착한 레드오션이다. 단독 금융 슈퍼앱(송금·대출중개)으로 가면 한패스·glow·은행에 진다. 이길 수 있는 단 하나의 좁은 길은 "검증된 고용·재직·임금 신호의 B2B 우선 공급자(데이터 레이어)"이며, 직접 송금사·CB사·대출중개가 되려는 시도는 즉시 접어야 한다.**

1. **시장은 크고 실재한다(매력도 高)**: 개인 해외송금 시장 약 11조원 규모 `[2차]`, 5대 은행 외국인 고객 697만('26.3) `[2차]`, 외국인 금융소외(thin-file)는 금융위 신용평가체계 개편 TF의 공식 의제 `[1차]`. 페인·수요·정책 우산 모두 확인.

2. **그러나 금융연계 3개 하위시장(송금·신용/대출·카드)에 이미 강한 선점자가 있다(right-to-win 낮음)**:
   - 송금: **한패스 매출 550억·송금 3조원·MAU 40만('24~'25)** `[2차]` — 이미 외국인 금융 슈퍼앱으로 진화(송금+대출연계+행정+구인구직).
   - 대출/신용: **신한 SOL 글로벌론(급여 3개월 수령 요건)·하나 EZ Loan** `[2차]` 이미 출시 — 은행이 "급여=신용신호"를 직접 쓴다. **NICE Welko('26.6.9)** `[2차]`가 외국인 eKYC+해외CB연계로 진입.
   - 카드: **E9pay 신한카드('25.5, 16개국어)** `[2차]` — 송금사(이나인페이)×카드사 BaaS형 제휴 선례.

3. **PlugNX의 진짜 right-to-win = 송금/대출/카드 그 자체가 아니라, 그들 모두가 목말라하는 "검증된 고용·재직·임금 데이터"의 B2B 공급**. 신한이 "3개월 급여 수령"을 요건으로 쓰고 NICE Welko가 "해외 CB"에 의존한다는 사실이 역설적으로 우리 길을 비춘다 — **국내 고용·임금 데이터는 아무도 못 가진 입력값**이고, VisaDesk가 그 입구다.

4. **냉정한 LTV 판정**: 금융연계가 환급의 1회성을 구원하려면 "재직 중 반복거래"가 실제로 우리 채널을 통해 일어나야 하는데, 반복거래(송금·카드결제)는 한패스·은행 앱에서 일어나지 너의 환급 앱에서 일어날 이유가 약하다. **현실적 LTV는 "직접 금융수익"이 아니라 "데이터 송객·신호 라이선스 수수료"이며, 단가는 낮고 규제 의존적이다.** 희망회로(직접 인터체인지·예대마진)는 금지.

**한 줄**: *"금융연계는 BM이 아니라 데이터 해자의 출구다. 우리가 금융사가 되려 하면 늦었고, 금융사에게 데이터를 파는 길목이면 이길 수 있다."*

## 2. 기존 제휴·진입 사례 — 무엇이 되고 안 되는가

### 2.1 핀테크(송금) — 한패스가 보여준 "되는 길"과 그 함의

- **한패스(되는 모델)** `[2차]` mt.co.kr: 매출 290억→**550억('24, +89.6%)**, 영업이익 44억(+153.8%), 흑자전환, MAU 40만, 송금 400만건·**3조원('24)**, IPO 추진. 서비스 = 송금+대출연계+교통카드+항공권+모바일충전+행정+공과금+구인구직. **외국인 직원 50%.**
  - **함의(냉정)**: 한패스는 이미 "외국인 B2C 슈퍼앱"이 되었다. BackWon이 송금·생활금융 슈퍼앱으로 정면 진입하면 **5년·MAU 40만·흑자 선점자와 정면충돌** → no-go.
- **센트비·와이어바알리** `[2차]`: 송금 전문, 수수료 경쟁. 누적거래 10조 주장(IPO 준비사) `[확인필요]`.
- **수익화 난이도** `[해외]`: 송금 핀테크 흑자까지 Wise 6년·Remitly 14년. take rate 압박(digital MTO 평균 3.55% vs 은행 14.55%). → **송금은 박리·장기 게임, 신규 진입 비합리.**

### 2.2 은행·카드 — "급여·고용 신호에 굶주려 있다"

- 신한·하나·농협이 외국인 신용대출 잇달아 출시/검토 `[2차]`. **공통 병목 = 신용평가 입력값 부재.** → PlugNX가 풀 수 있는 정확한 페인.
- E9pay 신한카드 = **송금사(이나인페이)×카드사 제휴(BaaS형)** `[2차]`. → "외국인 접점 보유자 + 금융 라이선스 보유자" 제휴가 실제 작동하는 패턴. **PlugNX의 자리 = '검증된 재직·임금 데이터 보유자'로서 이 제휴 구도에 끼는 것.**

### 2.3 안 되는 것 (no-go 재확증)

- **N1 직접 송금업**: 한패스/센트비 선점·박리·장기. 우리가 소액해외송금업 라이선스 취득해 직접 송금 = 명백한 자원낭비.
- **N2 직접 대출중개·여신**: glow가 광주은행 대출법인 인수설로 가는 길. 대출모집·중개는 별도 규제(대출모집인)·평판리스크(외국인 대상 고금리 중개 = 착취 내러티브). 직접 진입 회피.
- **N3 직접 CB(신용평가업)**: 신용정보법상 본허가 필요. NICE·KCB 영역. 우리는 CB가 아니라 **CB·은행에 신호를 파는 데이터 제공자**여야 한다(적격성 `[확인필요]`).

## 4. "환급=1회성" → 금융연계로 LTV 전환, 냉정 평가

### 4.1 전환 가설의 구조

```
환급(1회성, 출국 트리거)  →  재직 중 반복거래(송금·카드·대출)로 LTV 연장  →  ForeignID L3+고용/임금 신용신호로 금융사 송객/라이선스
```

### 4.2 냉정한 판정 (Right-to-win)

- **반복거래는 우리 앱에서 안 일어난다(약점)**: 송금은 한패스·은행, 카드결제는 발급은행 앱, 일상금융은 이미 잡힌 채널. 환급 입구로 들어온 유저가 **왜 송금·카드를 굳이 BackWon에서** 하는지에 대한 답이 약하다 → **직접 거래 LTV 가설은 취약.**
- **그러나 "신호 공급" LTV는 성립 가능(강점)**: 유저가 우리 채널에서 거래하지 않아도, **VisaDesk가 보유한 고용·재직·임금 데이터 + ForeignID 동의**를 금융사에 신호로 제공하면 거래는 은행에서 일어나고 우리는 송객/라이선스 수수료를 반복 수취. **이게 1회성→반복수익의 유일한 현실 경로.**
- **Right-to-win 원천(냉정 채점)**:

| 원천 | 강도 | 근거 |
|---|---|---|
| 검증된 국내 고용·임금 데이터 | ★★★★☆ | 신한이 "급여 3개월"을 쓰고 NICE는 본국 CB만 씀 = 우리 입력값이 진짜 빈칸 |
| ForeignID L3 동의·eKYC | ★★☆☆☆ | eKYC는 성숙시장(ARGOS·알체라)+NICE Welko도 진입 → 차별성 약 |
| B2B 입구 CAC0 | ★★★★☆ | 4사·송금사 모두 못 가진 채널 우위 |
| 정책 우산(신용평가 TF·대안신용) | ★★★☆☆ | 제도화 진행 중이나 외국인 데이터 라이선스 적격성 미확정 |
| 직접 송금/대출/카드 운영 | ★☆☆☆☆ | 선점자 압도, 진입 비합리 |

### 4.3 경쟁 속도전 (신용스코어 길목)

- **선두 신호**: NICE Welko 이미 출시('26.6.9, 해외CB)·vivisa×클링커즈 개발중('25.12)·신한 자행모형 가동. → **"외국인 신용 인프라" 길목은 이미 레이스 시작.**
- **PlugNX의 차별 무기 = 입력 데이터의 종류**: 경쟁자는 본국CB/통신/유학/자행급여. 우리만 **다수 고용주에 걸친 검증 재직·임금**. 단 **속도가 생명** — VisaDesk PoC에서 고용·임금 데이터 축적을 즉시 시작하지 않으면, 은행이 자행 데이터·NICE가 표준을 굳혀 길목이 닫힌다.

## 5. 권고 + De-risking

### 5.1 권고 (Answer)

1. **포지셔닝 고정**: 금융연계 = "BackWon이 금융사가 되는 것"이 아니라 **"금융사·CB에 검증 고용·임금 신호를 공급하는 데이터 레이어 + 송객 연결"**. IR·제품에서 "외국인 대출/송금 슈퍼앱" 표현 금지.
2. **수익은 송객(단기)→신호 라이선스(중기)**: 직접 인터체인지·송금마진·예대 가정을 BM에서 제거. business-case 유닛이코노믹스의 금융연계 라인을 이 두 가지로 재작성 제안.
3. **속도전 대응**: VisaDesk PoC 8주에 "고용·재직·임금 데이터 적재 + ForeignID 동의 플로우"를 게이트로 포함(NICE/은행/glow 선점 전 입력자산 확보).

### 5.2 go/no-go 기준 (디리스킹 실험)

| 실험 | 산출 | go 기준 | no-go 시 |
|---|---|---|---|
| **신용정보법 적격성 법률검토** | 재직·임금 신호의 합법 제공범위(CB/은행 대상, 본허가 불요 여부) | 동의기반 신호 제공이 합법 | 신호 라이선스 BM 폐기 → 송객만 |
| 은행·CB RFI(신한·하나·NICE·KCB) | "국내 고용·임금 데이터에 지불의사 있나·단가" | 1곳 이상 유료 PoC 의향 | 데이터 BM 보류 |
| 송객 전환·단가 실측 | 카드·대출 리퍼럴 CPA/전환율 | LTV>CAC(CAC0 전제) 흑자 | 금융연계 무료 훅으로만 |
| 한패스·glow 워치 | 그들이 고용·재직 데이터로 북상하는가 | 미진입=빈칸 유효 | 차별성 재설계 |

### 5.3 SSOT 갱신 제안 (단정 아님)

- PROJECT.md 경쟁해자: "**NICE Welko('26.6.9, 외국인 eKYC+해외CB)·한패스(송금 3조·MAU40만 슈퍼앱)**"를 신용·송금 길목 경쟁자로 추가 검토. glow뿐 아니라 한패스·은행·NICE가 실질 경쟁군.
- BackWon 금융연계: "직접 금융수익(인터체인지·송금마진) 가정 제외, 송객+신호 라이선스 중심, 신용정보법 적격성 `[확인필요]`" 명시 제안.
