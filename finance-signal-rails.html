팔지 말고, 동의받아
두 번 수익화한다.

외국인의 동의받은 고용·환급 데이터를 "DB로 팔지" 않는다. ① 본인에게는 대출비교·연결(송객 수수료), ② 금융사에는 검증 신호 API(이용료)로 — 한 번 모은 동의를 두 갈래로 수익화한다.

레일1 대출 송객(중개) 레일2 검증 신호 API 금지 raw DB 판매·무허가 스코어 엔진 ForeignID 동의 + VisaDesk 고용데이터
한 문장 컨셉

"외국인의 동의받은 고용·환급 데이터를 팔지 않는다 — 본인에겐 대출연결, 금융사엔 검증 신호 API로 두 번 수익화한다."

"DB를 판다"는 신용정보법·개인정보보호법상 봉쇄된다. 합법 활로는 데이터를 *팔지 않고* 동의 기반으로 ① 가공된 신호를 API로 제공하고 ② 본인을 대출에 연결(송객)하는 것. 두 레일은 같은 동의 퍼널을 공유하며 서로를 먹인다.

왜 "자연스럽게" 도는가 · 앱에서 대출연결을 하면 그 과정에서 동의·데이터가 쌓이고, 그게 금융사에 줄 신호의 재료가 된다. 단 레일1(송객 수수료)은 등록만 하면 바로 돌지만, 레일2(API 이용료)는 "사겠다는 금융사 LOI"가 선행돼야 한다("API를 만들면 자동으로 돈"이 아님 — 기존 검증서 은행 지불의사 low6·med3·high0).
신호 출처 · 난이도가 다르다

재직증명은 즉시, 이체내역은 마이데이터 후행.

같은 "금융 신호"도 어디서 오느냐에 따라 합법 난이도가 완전히 갈린다.

신호출처우리가 줄 수 있나단계
재직·고용·임금 증명VisaDesk (고용주가 검증) = 우리 데이터✅ 동의만 받으면 즉시 제공즉시 · FW-01
이체내역(계좌 거래) 증명은행·계좌 = 금융사 데이터⚠️ 마이데이터(본인신용정보관리업) 허가 영역 — 직접 수집 불가후행 · FW-09
이체내역을 당장 쓰려면 두 길 — ① 사용자 본인제출(본인이 거래내역서 업로드, 가벼움) ② 오픈뱅킹·마이데이터 사업자 제휴(자체 허가는 인허가 후행). 재직·고용 신호만으로도 1차 맞춤 비교·연결은 즉시 가능하므로, 이체내역 결합은 "정밀 맞춤"을 위한 후행 강화다.
개개인 맞춤 대출 추천·금리 비교

누가 "추천·금리"를 정하느냐로 갈린다.

맞춤 추천은 가능하다. 단 추천·금리·승인 결정의 주체가 금융사여야 무허가 신용평가 경계를 넘지 않는다.

방식 A · 즉시 · 권장 시작점

신호 공급 + 비교·연결

우리는 검증 신호만 금융사에 주고, 금융사가 자기 금리를 제시하면 우리가 비교·연결(송객). "추천·금리"의 주체는 금융사.

필요 · 대출성 상품 판매대리·중개업 등록(금소법) — 그게 전부
방식 B · 후행 · 본격 플랫폼

직접 대출비교 플랫폼 (토스·핀다형)

우리가 직접 "당신에게 A은행 3.5%·B캐피탈 6%" 맞춤 비교를 제시. 더 강력하지만 인허가 부담 큼.

필요 · 대출중개업 + 마이데이터(이체내역) + 다수 금융사 제휴
넘으면 안 되는 선

레드라인 — 이건 하면 안 된다.

⛔ 금지

  1. 재직·급여·체류 raw DB의 금융사 직접 판매 (신용정보법)
  2. 무허가로 "신용평가/신용점수" 산출·제공 — "맞춤 추천"이 우리가 신용을 판정하는 걸로 보이면 경계
  3. "대출 승인·한도·금리 보장" — 최종 금리·승인은 금융사 권한
  4. 이체내역 무허가 집계 (마이데이터 위반)
  5. 외국인등록번호(고유식별정보) 별도 동의 없는 수집·결합·이전
공통 게이트 · 외국인등록번호 별도 동의·분리보관·암호화·국내저장을 제품 1일차부터 분리 설계. 표현은 "DB 판매"→"동의 기반 신호 제공", "신용평가"→"대안정보 참고 신호", "대출"→"제휴사 상품 비교·연결(심사는 금융사)". 본 페이지는 참고용이며 신용정보법·금소법·개인정보보호법 조문·시행일은 변호사 검토 필요.

참고용 안내. 본 컨셉의 규제 판단은 법적 효력이 없으며 신용정보법·금융소비자보호법·개인정보보호법·자격사법 조문·시행일은 변호사·금융규제 전문가 검토가 필요하다. Signal API의 신용정보법상 지위는 금융위 비조치의견서로, 대출 송객은 금소법 중개업 등록으로, 이체내역·스코어는 마이데이터·전문개인신용평가업 인허가로만 합법화된다. 모든 수익·지불의사 수치는 목표·가정이며 금융사 LOI 실측 대상이다. 민감정보(외국인등록번호·여권·계좌)는 예시·로그에 실제 값을 남기지 않는다.
