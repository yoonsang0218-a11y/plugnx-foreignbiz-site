# ForeignID 제품 전략 1페이저 — 외국인 본인인증 인프라 (임원용)

작성일: 2026-06-15 · 작성: foreignid-auth × pm-product-strategy(business-model · lean-canvas · monetization-strategy) · 대상: 경영진/투자검토
프레임: ForeignID L0~L3 점진적 신뢰(progressive trust) + Lean Canvas + 수익모델 시나리오

---

## 핵심 결론 (Answer-first)

1. **ForeignID는 기능이 아니라 자산이다.** VisaDesk·BackWon이 각자 만들 외국인 eKYC를 **하나의 공통 인증 레이어로 합치면**, 두 제품의 KYC 원가가 한 번만 발생하고, 그 위에 외부 eKYC API 매출이 얹히는 **플랫폼 자산화** 구조가 된다.
2. **단기 권고는 "외부 API 사업화"가 아니라 "내부 원가센터 → 자산화 준비".** PoC 8주 동안은 L1·L2를 VisaDesk 근로자 등록/BackWon 자격조회의 **내부 인증**으로만 깐다. 외부 API 과금은 L2 진위확인 정확도와 법무 라인이 검증된 뒤 여는 **옵션(2단계 게이트)** 으로 둔다.
3. **가장 중요한 단일 권고:** L3(계좌+전자서명, 금융거래)은 특금법 AML·전자금융거래법·전자서명법 레드라인 구간이므로 **PoC 범위에서 분리**하고, BackWon 환급금 수령 직전에만 step-up 하는 **행위 시점 인증**으로 한정한다. L3을 서둘러 열면 규제 리스크가 사업 전체를 막는다.
4. **right-to-win:** 경쟁 4사(vivisa·dagachi·vijob·glow)는 **자체 인증/B2B 고용데이터를 보유하지 않는다**[출처:handoff/research-b2c-apps.md, 2026.6]. vivisa×glow 동맹이 노리는 "비자데이터→대체 신용평가" 길목은 **인증된 신원 + 검증된 고용·임금 데이터**가 있어야 성립 — 그 두 입력을 동시에 쥔 곳은 PlugNX뿐이다. ForeignID가 그 해자의 잠금장치다.

## 1. 문제 · 대상 (Why now / Who)

### 문제
외국인 신원확인은 한국 서비스의 **공통 마찰점**이다. 내국인 휴대폰 본인확인 한 방으로 끝나는 절차가, 외국인은 여권·외국인등록증(ARC)·체류자격·통신 명의·계좌 실명이 모두 따로 놀아 **제품마다 인증을 새로 만든다**. PlugNX 내부에서도 그대로 재현된다 — VisaDesk가 근로자 신원을 확인하고, BackWon이 환급 수령자 신원을 또 확인하면 **같은 일을 두 번** 한다.

### 대상 (3개 수요처)
| 대상 | 어떤 인증이 필요한가 | 필요 레벨 |
|---|---|---|
| **VisaDesk (B2B)** | 기업이 등록하는 외국인 근로자가 "실재하고 합법 체류 중인가" | L1→L2 |
| **BackWon (B2C)** | 환급 자격 조회는 신원·체류, 환급금 수령은 금융거래 | L2 / 수령 시 L3 |
| **외부 파트너 (잠재)** | 외국인 고객을 받는 금융사·플랫폼·행정/HR SaaS의 eKYC 위탁 | L1~L3 API |

대상 규모(배경): 체류외국인 2,783,247명 · 장기체류 2,159,052명 · 취업자격 594,047명 [출처:법무부 출입국·외국인정책 통계, 2025.12말 / cf. pack#10]. 이 모수를 SSOT 정본 값으로 환산하면 인증 레이어의 잠재 처리 모수는 **TAM B2C 216만**(전체 장기체류) · **TAM B2B 49만**(E계열 취업비자), 체류외국인 모집단 **278.3만** [SSOT].

## 2. 3단계 레벨 — 신뢰수준 · 유스케이스 · 검증요소

> 점진적 신뢰: 행위가 요구하는 신뢰수준에 맞는 **최소 레벨만** 요구(과도 수집 금지). 상위는 하위를 포함하며, 하위 요소 만료 시 강등될 수 있다. [출처:foreignid-auth/auth-levels.md]

| 레벨 | 신뢰수준(틀린 사람 허용 시 피해) | 추가 수집 | 핵심 검증요소 | 대표 유스케이스 |
|---|---|---|---|---|
| **L0** | 없음 | 이메일·약관 동의 | — | 가입, 공개 콘텐츠 열람 |
| **L1** | 낮음 — 신원 기본 | 여권 + 셀카 | 여권 OCR(MRZ 체크디지트)·위변조 점검 + **라이브니스** + 여권사진↔셀카 대조 | VisaDesk 근로자 1차 등록, BackWon 개인화 열람·저위험 신청서 |
| **L2** | 중간 — 체류·연락 | + 외국인등록증(ARC) + 통신(휴대폰 본인확인) | ARC OCR·위변조 + L1과 성명·생년월일 **교차일치** + 체류자격/만료일 유효성 + 통신사 명의 일치 | VisaDesk 근로자 확정 등록·서류, **BackWon 환급 자격조회** |
| **L3** | 높음 — 금전 이동·계약 | + 본인 명의 계좌 + 전자서명 | 계좌 실명/예금주 일치(예: 1원 인증) + L2와 명의 일치 + 전자서명 무결성 + (금융 시) **AML 스크리닝** | **BackWon 환급금 수령**, 금융상품 연계, 전자계약 체결 |

검증 파이프라인(예시): 캡처 → GPT-4V OCR → 필드검증 → 진위/위변조 → 통신·계좌 → 전자서명. 진위확인 API 사양·정부 DB 대조 가능범위·정확도는 변동 → **도입 전 최신 확인**.

실패 처리(공통): 자동 거절 대신 **수기 검토 큐**로 경계 사례 구제, 다국어(BackWon 6개 언어) 사유·다음행동 안내, 실패 로그도 마스킹(`M********`).

## 3. 플랫폼 자산화 BM (Lean Canvas 압축)

핵심 논리: 두 제품이 따로 만들 인증을 **공통 KYC 레이어 하나**로 합치면 → 원가가 1회로 수렴 + 인증된 신원·체류·고용 데이터가 한 곳에 축적 → 그 위에 **외부 eKYC API 과금**을 얹는 자산화.

| 블록 | 내용 |
|---|---|
| **문제** | ① 제품마다 외국인 인증 중복 구축(내부 원가 낭비) ② 외부 금융·플랫폼도 외국인 eKYC 난제(여권·ARC·체류·계좌 통합 부재) ③ 경쟁사의 "데이터→신용" 길목에 **인증된 신원**이라는 전제가 비어 있음 |
| **고객 세그먼트** | (내부) VisaDesk·BackWon / (외부) 외국인 고객 받는 금융사·송금·HR/행정 SaaS·플랫폼 |
| **UVP** | "여권→ARC→통신→계좌→전자서명을 **한 번에, 점진적으로** 묶는 외국인 전용 eKYC 레이어 — 게다가 **검증된 고용·체류 데이터와 연결**된 유일한 인증" |
| **솔루션** | L0~L3 progressive trust · GPT-4V OCR + 위변조/라이브니스 · step-up 인증 · 다국어 실패 구제 |
| **불공정 우위 (right-to-win)** | ① 경쟁 4사 모두 자체 인증·B2B 고용데이터 미보유[출처:handoff/research-b2c-apps.md, 2026.6] ② 양면 데이터(고용·임금 + 신원) 결합 ③ 정책 정합성(체류·환급 도메인) ④ 두 제품을 동시에 쥔 **재사용 인프라**라 한계원가↓ |
| **채널** | (내부) 제품 내장 / (외부) API·SDK, 파트너 영업, 행정사·노무사 네트워크 레퍼럴 |
| **수익원** | (내부) 인증 원가 절감(중복 제거) / (외부) eKYC API 건당·구독·티어 과금 |
| **원가구조** | OCR/AI 추론 · 진위확인·통신·계좌 인증 **외부 API 변동비** · 보안/암호화·감사 · 컴플라이언스·법무 |
| **핵심지표** | L1→L2 승급률 · 인증 성공률(레벨별) · 오탐/수기검토 비율 · 건당 인증원가 · (외부) API 호출수·매출 |

> 자산화의 핵심 지표 — **건당 인증원가**: 내부 두 제품이 공유할수록 분모(인증 건수)가 커져 단위원가가 떨어지고, 외부 API는 그 떨어진 단위원가 위에 마진을 얹는다.

## 4. 수익모델 시나리오 (내부 원가절감 + 외부 API 수익)

> 모든 금액은 **목표(가정)/추정**이며 확정 매출 아님. 실제 단가는 진위확인·통신·계좌 API 외부 변동비와 협상에 좌우 → 검증 필요.

### 가치 축 1 — 내부 원가절감 (지금 확실한 가치)

- 메커니즘: VisaDesk 근로자 등록 인증 = BackWon 자격조회 인증을 **공유** → 플라이휠상 기업이 근로자 등록 시 이미 끝난 L2 신원이 BackWon으로 **그대로 이월**(전환 60%+, CAC 0의 인증판 등가물) [SSOT, 플라이휠].
- 효과: 중복 KYC 구축·운영비 제거, 사용자 재인증 마찰 제거(전환률 보호). [추정] 자산화 1단계의 ROI는 외부 매출 이전에 **여기서 먼저 확정**된다.

### 가치 축 2 — 외부 eKYC API 수익 (2단계 옵션)
monetization-strategy의 모델 매핑:

| 모델 | 적용 형태 | 적합 대상 | 리스크 |
|---|---|---|---|
| **Usage-based(건당)** | 인증 1건당 과금(레벨별 차등: L1<L2<L3) | API 호출 변동 큰 파트너 | 매출 변동성·고객 원가불안 |
| **Subscription(구독)** | 월 정액 + 포함 건수, 초과분 usage | 꾸준한 외국인 고객 받는 금융/HR SaaS | 초기 볼륨 확보 |
| **Tiered(티어)** | L1 저가 게이트 → L2/L3 고마진 | 단계별로 신뢰가 필요한 파트너 | 티어 설계 복잡도 |

### 3개 시나리오 (라벨: 목표/가정)
| 시나리오 | 내부 | 외부 API | 전제 |
|---|---|---|---|
| **A. 내부 전용(보수)** | 두 제품 인증원가 1회 수렴 | 0 | PoC 단계 기본값. 외부 미개방 |
| **B. 셀렉트 파트너(기대)** | 동일 | 소수 파트너 usage+구독 파일럿 | L2 진위 정확도·법무 통과 후 |
| **C. eKYC 플랫폼(확장)** | 동일 | 티어형 다파트너, 신용스코어 데이터 연계 | L3 규제 정합·AML 라인 확립 후 |

> 시나리오 B/C 진입은 본 페이저 §6 게이트 통과가 전제. 외부 단가·물량은 [가정]이며 파일럿으로 검증.

## 5. 규제 레드라인 (참고용 · 법무 검토 필요)

> 아래는 **설계 점검용**이며 적용·해석·법적 효력은 법무·컴플라이언스 확정 사항(참고용, 법적 효력 없음). [출처:foreignid-auth/security-privacy.md]

| 영역 | 레드라인 | 분기 |
|---|---|---|
| **개인정보보호법 / 고유식별정보** | 여권번호·외국인등록번호는 고유식별정보 → **별도 동의·암호화(전송+저장)·보관기간·파기** 필수. 생체(라이브니스)는 목적제한·최소·즉시파기 지향 | L1부터 |
| **특금법 AML/CFT** | L3 금융거래 시 고객확인(CDD/EDD)·의심거래(STR)·제재대상 스크리닝 기준 정의(운영·기준 FIU 최신 확인) | **L3만** |
| **전자금융거래법 · 전자서명법** | 전자금융 안전성 요건 · 전자서명 무결성/부인방지/증적 보존(효력 판단은 참고용→법무 확정) | **L3만** |
| **신용정보법** | 계좌 등 신용정보 수집·이용 근거·동의·마스킹·접근통제 | L3 / 신용연계 |
| **위탁·국외이전** | 진위·통신·계좌 제3자 API, 클라우드 리전 → 고지·계약·보호조치, 응답 평문 미저장 | 전 레벨 |
| **표현 레드라인** | 비자 "대행" 표현 금지 — **연결(라우팅)·준비지원**만(행정사법). 인증을 "정부 공인"으로 오인시키는 표현 금지 | 전 레벨 |

**설계 7대 원칙 적용**: 수집 최소화 · 목적 제한(VisaDesk↔BackWon 공유는 동의 범위 내) · 보관기간 한정(원본 이미지 단기 파기, 결과 플래그만 보존) · 암호화 · 단계별 분리 동의(다국어) · RBAC+감사로그 · 비식별/마스킹.

## 6. go/no-go 기준 + 검증 실험

### Stage Gate (자산화 단계별)
| 게이트 | 통과 기준 (go) | 미달 시 (no-go/대안) |
|---|---|---|
| **G1 — 내부 인증 가동** | L1·L2 인증 성공률 목표치 도달[가정], 수기검토 비율 관리가능, VisaDesk↔BackWon 신원 이월 동작 | 외부는 닫고 내부 원가절감만 수확. OCR/진위 정확도 개선 후 재시도 |
| **G2 — 외부 API 개방(시나리오 B)** | L2 진위확인 정확도·오탐 통제 검증 + **법무 라인 클리어** + 파일럿 파트너 1~2곳 WTP 확인 | 외부 미개방 유지. 내부 자산화로만 운영 |
| **G3 — L3 금융·전자계약** | 특금법 AML·전자금융·전자서명 **법무 확정** + AML 스크리닝 운영체계 + 환급 수령 step-up UX 검증 | L3 보류. 환급 수령은 기존 검증된 외부 경로로 우회, ForeignID는 L2까지만 |

### 검증 실험 (2~3개)
1. **L1/L2 인증 정확도·마찰 실험** — PoC 온보딩 근로자 표본(가정: 회사당 30~60명, 450~900명 규모[출처:pack#10])에 L1→L2 흐름 적용. 측정: 레벨별 성공률·승급률·수기검토율·소요시간. 결정기준: 성공률·오탐이 목표 내면 G1 go.
2. **외부 파트너 WTP 실험** — 외국인 고객 받는 금융/HR SaaS 5~10곳 인터뷰 + 건당/구독 가격 제시(landing+interview). 측정: 제시가 수용·예상 호출량. 결정기준: 2곳 이상 유의미 WTP면 G2 파일럿.
3. **신원 이월(자산화) 실험** — VisaDesk에서 L2 통과한 근로자가 BackWon 자격조회에 **재인증 없이** 진입하는 비율·전환영향 측정. 결정기준: 이월이 전환률(플라이휠 60%+ 가정[SSOT])을 보호하면 내부 자산화 ROI 확정.
