## 핵심 결론 (Answer-first)

1. **glow의 Brand DNA = "외국인의 매일의 금융 동반자"** — B2C 라이프사이클 슈퍼앱(17개 언어 [주장]·무료), BM은 **대출중개 커미션 단일 기둥** + 송금·통신·채용 인접 확장. 자체 환급 트랜잭션·자체 본인인증·B2B 고용데이터는 **여전히 부재**([출처: handoff/research-b2c-apps.md, 2026-06-10 재확인]).
2. **포지셔닝 갭 = glow는 "B2C 폭(breadth)"을, PlugNX는 "B2B2C 깊이(depth)·데이터 원장"을 점유** — 2×2(데이터 소유 vs 수익 모델)에서 두 회사는 **다른 사분면**. 정면 충돌이 아니라 **데이터→신용 길목(C2)에서만 교차**.
3. **단일 최중요 위협 = vivisa×glow 동맹(2025.12)의 "비자데이터→대체신용평가"** — glow가 약한 "검증된 신원·근로 데이터"를 vivisa의 유학생 데이터로 메우려는 수. PlugNX의 ForeignID+고용·임금 데이터가 같은 길목을 노리므로 **속도전**.
4. **우리 공백 우위 = ① 환급 트랜잭션(돈을 '비교'가 아니라 '회수') ② 자체 ForeignID(중개가 아닌 인증 인프라) ③ B2B 고용·임금 원장(글로우엔 없는 1차 데이터)** — glow가 따라오려면 B2B 영업조직과 인증 라이선스를 새로 지어야 함(전환비용·시간 해자).
5. **권고 메시지 한 줄**: glow가 "비교·중개(brokerage)"라면 PlugNX는 **"회수·기록(recovery & record)"** — *"비교는 글로우에, 받는 건 BackWon에"* 로 카테고리를 분리해 정면 경쟁을 회피하고 제휴 옵션까지 연다.

## B. PlugNX × glow 포지셔닝 2×2

### 2×2 — 가로축: 데이터 소유(중개 의존 ↔ 1차 데이터 보유) / 세로축: 가치 형태(정보·비교 ↔ 트랜잭션·회수)

```
              트랜잭션·돈을 "회수/실행"
                        ▲
                        │
   (외부 데이터 의존)    │   ★ PlugNX BackWon+VisaDesk+ForeignID
   잠재: 신용중개 슈퍼앱 │   환급 회수 + 자체 인증 + B2B 고용·임금 원장
   (glow가 동맹으로 가려 │   = 1차 데이터 × 트랜잭션 (우리 단독 사분면)
    는 방향)            │
────────────────────────┼────────────────────────▶ 1차 데이터 보유
                        │
   ● glow(현재)         │   ○ vivisa(현재)
   대출·송금 "비교/중개" │   유학생·대학 1차 데이터
   17개 언어 폭·무료     │   (단 트랜잭션 약, B2C 얕음)
   = 외부데이터 × 정보   │
                        │
              정보·비교만 제공
                        ▼
   ↑ vivisa×glow 동맹(2025.12) = 좌하단 두 점을 합쳐
     "우상단(우리 자리)"으로 북상하려는 화살표 = 직접 위협
```

**해석:**
- glow는 **좌하단(외부데이터×정보비교)** — 폭은 넓으나 자기 데이터·트랜잭션이 얕다.
- PlugNX는 **우상단 단독 점유**(1차 고용데이터 × 환급 트랜잭션 × 자체 인증).
- **동맹의 의도 = 좌하(glow 금융)+우하(vivisa 데이터)를 합쳐 우상단으로 북상.** 즉 그들의 약점(데이터/트랜잭션)을 서로 메워 **우리 사분면을 노린다.** 이것이 핵심 경쟁 신호.

## C. 공백 우위 (Right-to-win) — 우리가 이기는 3축

| 축 | glow | PlugNX | 왜 따라오기 어려운가 (해자) |
|---|---|---|---|
| **① 환급 트랜잭션** | 대출·송금 **비교/중개**만(커미션) | 미수령 연금·퇴직금·출국만기보험 **실제 회수**(BackWon) | 회수는 고용·재직·임금 데이터가 있어야 정확. glow엔 그 1차 데이터가 없음 |
| **② 자체 ForeignID 인증** | KYC를 제휴 은행에 의존 | L1 여권+셀카 → L2 +외국인등록증+통신 → L3 +계좌+전자서명 자체 인프라 | 인증은 라이선스·기술·반복재사용 자산 → 중개앱이 단기 복제 불가 |
| **③ B2B 고용·임금 원장** | 없음(채용은 입구만) | VisaDesk가 기업의 고용·체류·임금·서류를 상시 기록 | B2B 영업조직·기업 신뢰·데이터 축적 = glow의 B2C DNA와 정반대, 새로 지어야 함 |

**플라이휠 우위:** 기업이 근로자 등록 → 근로자 BackWon 자동유입(전환 60%+, CAC 0) `[SSOT]` → 근속률↑ → B2B 유지. glow는 **B2C 광고/중개로 한 명씩 유료 획득**해야 하므로 CAC 구조부터 열위. ([출처: handoff/research-b2c-apps.md]: B2C 4사 전원 B2C-first 수익화 정체 = 이 구조의 실증.)

## D. vivisa×glow 동맹 위협 — 무엇을·언제 경계하나

- **무엇:** 2025-12-18 MOU. glow의 외국인 행동 데이터 + 예스퓨처(vivisa)의 비자·행정 데이터를 결합 → ① **외국인 특화 대안신용평가 모델(ACSS)** ② 소액 신용대출·**후불결제(BNPL)** ③ **입국 전(onboarding) 금융** 공동기획. glow×vivisa 서비스 연동으로 대학·지자체용 "외국인 정착 통합 지원 시스템" 구축. [출처: 뉴스프라임 2025-12-19; 벤처스퀘어 2025-12-18]
- **왜 위협:** 우리 ForeignID 신용스코어 thesis(C2)와 **동일 방향·동일 길목**. 그들은 **유학생(D계열) 데이터 입구**, 우리는 **고용·임금(E계열) 데이터 입구** → 누가 먼저 "검증된 외국인 근로 데이터로 신용을 만든다"를 선점하느냐의 **속도전**. 특히 BNPL·입국 전 금융은 **트랜잭션화 의지**의 신호 — 비교·중개 레이어를 넘어 실행 레이어로 북상하려는 첫 수다.
- **우리 비대칭 우위:** 유학생 데이터(소득·재직 약함)보다 **고용·임금 데이터가 신용 예측력이 높다** `[가정: 재직·소득 변수의 디폴트 예측력 우위]`. 즉 길목은 같아도 **데이터 품질에서 우리가 우위.** 단 속도에서 지면 "선점 내러티브"를 빼앗김.
- **워치 트리거(분기):** ① 동맹의 ACSS 신용평가 제품 **실출시** ② glow **환급 기능** 출시 ③ glow/vivisa **기업용(B2B) 제품** ④ glow **자체 인증/송금·BNPL** 정식 출시 ⑤ 양사 **Pre-A 이상 펀딩**. ([출처: handoff/research-b2c-apps.md] G4와 정합 — 본 분석은 그중 ①③④를 brand-DNA 근거로 구체화하고 ACSS/BNPL 디테일을 추가.)

## E. 우리가 취할 메시지·해자 액션 (5)

1. **카테고리 분리 메시징 — "비교는 글로우에, 받는 건 BackWon에"**
   glow를 *brokerage(비교·중개)*, 우리를 *recovery & record(회수·기록)*로 못박는다. 정면 기능 경쟁 회피 + "우리가 더 깊다"를 한 줄로. (영문: *"glow compares. BackWon recovers."*) — 광고·랜딩·세일즈덱 헤드라인에 고정.

2. **신용 길목 선점 내러티브 — "임금 데이터가 진짜 신용이다"**
   동맹의 "비자데이터 신용"에 맞서 *"유학 데이터가 아니라, 실제 고용·임금 데이터가 외국인 신용의 정답"* 메시지로 우상단을 우리 것으로 프레이밍. IR·정책 readout에 K-Trust/대안신용 길목 right-to-win으로 삽입.

3. **PoC 즉시 데이터 해자 적재(속도전 대응)**
   8주 PoC(`[SSOT]` 15사·3,300만원)에서 ForeignID L2/L3 + 고용·임금 데이터 축적을 **1주차부터** 시작 → 동맹의 ACSS 출시 전에 "검증된 근로 데이터 N만 건" 카운터를 만든다. ([출처: handoff/research-b2c-apps.md] G3와 동일, brand-DNA가 우선순위 근거 보강.)

4. **제휴 옵션 열어두기(coopetition) — glow를 채널로**
   glow는 환급·인증·B2B 데이터가 없으므로 **충돌이 아니라 상호보완 가능**. "glow 커뮤니티에 BackWon 환급 콘텐츠 / glow 대출중개에 우리 ForeignID·근로데이터 신용 공급" 형태의 **데이터 공급자 포지션**도 백업 전략으로 설계(동맹에 맞불). 단, 우리 1차 데이터·인증은 라이선스로만 노출(원천 양도 금지).

5. **언어 갭 보강(전환율 방어)**
   환급·금융은 신뢰 게임 — BackWon 6개 언어 `[SSOT]` vs glow 15~17개 [주장]. 핵심 송출국(베·인니·네팔·태·우즈벡·몽골) 우선 확대 로드맵을 **B2C 전환 KPI에 직접 연결**([출처: handoff/research-b2c-apps.md] G1 구체화). 폭 전체를 따라갈 필요 없이 "회수 트랜잭션이 일어나는 상위 6~8개국"만 — 폭 경쟁이 아니라 **회수가 일어나는 언어에만 깊게**.

- **트랙션은 전부 벤더 [주장]:** glow의 MAU(5만~50만 충돌)·매출목표·언어수(15/17/80 충돌)·손익분기·제휴 120+는 사업자 발표로 **미검증**. 인용 시 반드시 `[주장]` 라벨, 보수적으로는 MAU 5만 상한으로 다룬다.
